# 后台提交分组独立复核

只读审查 `task_commit_review` 覆盖 TaskQueue.completeBatch、TaskCompletions、TaskWorker、ChannelGateway 的本轮改动及对应专项测试。无Git仓库，按明确文件范围审查，没有编辑、启动负载或派生代理，不覆盖无关历史功能。

发现并修复1项P2：新增结果事务包住同步apply时，证据冲突仍会在保留业务连接/锁的情况下申请REQUIRES_NEW连接，连接池紧张时可能阻断冲突证据保存及CONFLICT隔离。新增真实SQL事务挂起回归，修正前预期0、实际1（`.work/task-commit-conflict-connection-red.log`）。同步路径现先退出/回滚结果事务，再独立保存冲突；中间查询校验也只保存一次。回调apply原有独立证据事务保留。

修正后复核无新增P1/P2/P3：确认分组按PK顺序、整组提交、逐条租约fencing，提交返回后才向调用者公布结果，worker名额/心跳保持到结果确定。渠道原始回执先落库，财务变更与最终尝试状态同事务。

审查没有重跑测试；当时修正后的专项仍在运行，不将早期83+5项结果充当修正后全量结果。最终验证另见[验收记录](../quality/2026-10-19-task-commit-batching.md)。

覆盖边界保留：超过64个并发调用者切组（现有worker总上限32）；follower中断、多follower整组失败恢复；真实COMMIT断连后的结果未知；既有回调REQUIRES_NEW满池行为。它们没有被写成已专项通过，最后一项按本轮范围保持原语义。

追加范围：全量发现既有账单子查询错误选择PRIMARY、扫描21000行超过1500门槛后，同一审查者复核了局部JOIN_INDEX修正。提示位于内层SELECT、别名d正确，V4复合索引及InnoDB附带主键行号可覆盖查询；分页与重复判断不变，无新增P1/P2/P3。核对29项绿灯，三种分布均使用目标覆盖索引，原门槛未放宽。其他数据库版本/引擎未验证，未来重命名该索引须同步修改提示。
