# 503来源与提交观察器对照

本轮处理V1性能验收的前置问题：区分503的返回位置，测量在线提交观察对请求链路的影响。保留API在途16、持久化支付容量16桶×16、配额500/key/s、MySQL双1持久性及D0性能资源配置。schema仍为V12。

**结果：完整600秒预热及ABBA四轮取证已完成，697个503全部来自API_INFLIGHT；控制组关闭在线观察后仍有132/186次入口拒绝，未证明关闭观察器能改善拒绝或时延。29303笔受理全部过账且平衡。校准数据有效，但在线基线资格、300完成TPS及R1/D1仍未通过。**

## 实现与口径

503保留`RETRY_WITH_SAME_BUSINESS_KEY`业务错误码，增加`Retry-After: 1`与`X-Retry-Reason`固定枚举；不输出异常文本、商户、凭据、SQL或业务号。其他错误与成功响应不增加该分类头。

| 原因 | 含义 |
| --- | --- |
| API_INFLIGHT | 签名API入口未获得在途许可，尚未进入凭据/nonce/配额/业务处理 |
| QUOTA_CAPACITY | 配额批处理的数据库工作许可已满 |
| QUOTA_TIMEOUT / QUOTA_INTERRUPTED | 调用方等待配额结果超时或被中断，不释放仍在执行的数据库工作许可 |
| QUOTA_UNAVAILABLE | 配额组件关闭或执行器拒绝新工作 |
| QUOTA_DATABASE | 配额批处理执行/提交未成功确认，不发布额度 |
| PAYMENT_CAPACITY | 新支付对应逻辑桶未获得持久化容量；事务回滚 |
| DATABASE_UNAVAILABLE | 无法取得数据库连接或无法开启事务 |
| DATABASE_TRANSIENT | 其他可重试数据库异常，例如锁冲突 |
| UNCLASSIFIED | 未来503未指定原因，或压测收到缺失/未知分类头；不猜测来源 |

`merchantpay_api_unavailable_total{reason=...}`只使用固定枚举标签，在生成503的分支计数。MVC异常由Advice计数；签名过滤器只计数它自己处理的异常，避免同一响应重复计数。压测逐请求及汇总保存相同分类，与阶段前后服务端计数差核对。全局计数还可能包含其他手工流量；不一致时不得直接归因。

`merchantpay_api_stage_seconds_{count,sum,max}{stage=...}`计时范围：AUTH为凭据查询；NONCE为nonce持久化；QUOTA为等待配额提交结果；HANDLER为下游Web/业务处理及响应序列化。失败调用也计时。它们是调用方墙钟耗时，包含排队、连接、锁和提交等等待，不是单独的数据库CPU/提交耗时；不能据此直接宣布底层根因。

默认`full`观察器与原计量V2相同：独立连接读取已提交状态、平衡凭证与Outbox，用本机单调时钟给出提交可见性区间。新增`after`仅供对照：请求发送期间不启动观察器，结束后仍逐业务号核验提交与资金。该模式的完成TPS、完成P99、逐笔提交时间及在线观察间隔均为null，`onlineCompletionMeasured=false`，不能用于基线资格或正式性能验收。两种模式都不将5xx推断为未提交。

## 可复现入口

```powershell
# 服务已通过scripts/start-local.ps1 -Performance启动
& scripts/load/run-local.ps1 -Performance -Scenario pay -Rate 50 -SecondsOrPayments 60 -ObserverMode full
& scripts/load/run-local.ps1 -Performance -Scenario pay -Rate 50 -SecondsOrPayments 60 -ObserverMode after
# 完整600秒full预热，随后固定full/after/after/full四轮，默认每轮50/s×60秒
& scripts/load/baseline-local.ps1 -CalibrateObserver
```

完整协议沿用基线独占锁、每阶段真实资源/源码/JAR/进程/容器/监控指纹、资金及容量快照、渠道排空、诊断覆盖检查。四轮都带相同只读诊断。阶段前后另保存仅含固定API指标的`.prom`文件；`summary.json`标记`observerCalibration=true`，资格仍为false。对照协议正常退出仅表示取证完成，不代表系统通过性能门槛；普通基线资格规则不放宽。

ABBA次序可减轻部分单向预热/漂移影响，但数据继续自然增长，共享主机/WSL/存储也未隔离。比较HTTP响应及拒绝比例时同时报告所有轮次和发送延迟；`after`没有可比较的完成延迟。在线观察累计连接/查询时间不是CPU利用率。

## 验证与运行证据

新增回归覆盖入口/数据库/配额原因、MVC容量原因与单次计数、固定标签、未知分类清洗、离线对照无法获得在线基线资格。保留既有幂等、nonce顺序、配额提交后授权、调用方中断不归还数据库工作许可及支付容量回归。

全量后端284项平台+5项模拟器共**289项**、fmt及平台打包通过。新增定向测试16项通过；最终计量回归还运行真实MySQL未提交不可见、提交可见、回滚、偏移时间戳及平衡核验。资格守卫与离线计量测试通过。[独立复核](../reviews/2026-10-19-retry-observer-review.md)的两项P2已修复，复读后无剩余发现。前端业务未变，未重复前端/浏览器全套；远程CI及镜像扫描不在本轮。

初始只读预检发现旧业务PID已失效，8080/9091/5173未监听，MySQL仍运行；保留首次失败记录后核对真实数据库排空，再构建和恢复服务。MySQL数据未删除，缓存仍1GiB。受限环境的首次定向运行卡在Mockito附加后被停止，本机定向及全量回归通过；不以未完成的运行作为证据。

部署后真实100支付+20退款全部成功，120张凭证/359条分录平衡。平台新JAR摘要`1B63BC70F3A1BFB2EBEF64C1EDC5098D11F35C71DD50D3C966C31704DC2D2997`；旧平台JAR另存`.work/pre-retry-observer-platform.jar`。模拟器JAR不变。schema未变，回退应排空停机后替换平台JAR，不回退已发生的交易数据。
