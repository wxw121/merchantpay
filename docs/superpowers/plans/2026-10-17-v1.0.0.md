# V1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付商户支付与对账平台 V1.0.0 的完整业务闭环、前后端、独立渠道模拟器、部署与可执行验收。

**Architecture:** 模块化 Spring Boot 应用，以 MySQL 本地事务提交交易、退款额度、凭证和 Outbox。独立 HTTP 渠道模拟器使用独立持久化存储；React 管理端展示真实 API 数据。V1 使用持久化轮询任务，Kafka／Flink／ClickHouse 留在已批准的 V2／V3。

**Tech Stack:** Java 25、Spring Boot 4.1.x、Spring Modulith 2.1、Spring JDBC、Flyway、MySQL 8.4、OIDC／Keycloak、React 19.3、TypeScript 6、Vite 8、Ant Design 6、TanStack Query、ECharts、JUnit、Testcontainers、Playwright、k6。

**Spec:** [需求说明书](../specs/2026-10-17-merchant-payment-platform-design.md)、[三版规划](../../roadmap/three-major-releases.md)、[性能验收](../../quality/performance-and-resilience.md)。

## Global Constraints

- 本次用户明确要求开始实施 V1.0.0；需求说明书和技术方向已经确认。
- 支付状态、退款预占、记账与 Outbox 保持同一分片的本地事务原子边界。
- CNY；金额范围 1～1,000,000,000 分；API 金额为十进制整数字符串，禁止浮点资金运算。
- 手续费 0.6%，按累计成功退款计算本次手续费退还差额。
- 支付未知不改失败；退款未知不释放预占；重复事实不得重复有效入账。
- 支付与退款的业务号幂等；同键不同语义返回冲突。
- 商户隔离、签名、CSRF、下载授权、审计与 SSRF 防护不可省略。
- 默认不启用 Java preview；使用 ScopedValue、虚拟线程、HTTP 客户端分组和明确结果类型。
- V1 对账只做识别、查证与安全续跑，不开放 V2 的正式账务调整与结算审核。
- 所有界面上的业务数据来自 API；演示商户和模拟渠道明确标记。
- 性能、数据规模和长稳结果必须实测。没有运行的门槛保持未验收，不将代码完成等同于发布。
- 工具链与缓存置于项目内，不修改系统 Java、Node、Maven 配置；不购买云资源。

## Review Focus

1. 支付受理与渠道扣款之间进程中断：沿用渠道幂等请求键，未知结果可恢复。
2. 同一成功事实使用不同通知 ID 重复投递：按业务事件去重，而非只按通知 ID。
3. 两个部分退款成功顺序变化：累计手续费与预占结转仍然正确。
4. 账单失败后重跑或重复上传：保存原始证据，不发布半份正式结果。
5. 管理端、签名 API、游标及导出下载：任何入口都不能越权访问其他商户。
